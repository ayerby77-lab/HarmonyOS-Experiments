## 2. 数据流总览（目标态）

```
EntryAbility.onCreate(want)  ──┬─ KnowledgeSeeder.seedIfNeeded() ── anatomy_knowledge.db（幂等种子）
                              ├─ ArkAFIntent.publishQuestion(want.question)   ← 冷启动
                              └─ loadContent('pages/Index')
EntryAbility.onNewWant(want) ──── ArkAFIntent.publishQuestion(want.question)   ← 热启动（Ability 已在后台）

Index(首页) ──@StorageProp('arkaf.pendingQuestion')+@Watch── 有 pending → 打开 KnowledgeQA
   └─ KnowledgeRuntime.shared()  ← 进程唯一实例：ServiceContainer + KnowledgeIndexBridge + KnowledgeService

KnowledgeRuntime.init(context)：
   KnowledgeService.getInstance(ctx).ensureReady()
   container = new ServiceContainer({ useCloud, cloudFunctionUrl })
   bridge = await container.connectKnowledgeService(knowledge)   // 全量同步 + 订阅增量
        ↑ anatomy_knowledge.db 当前 revision 片段 → IndexSyncManager → MemoryVectorStore

KnowledgeQA：
   aboutToAppear  → runtime.acquirePage() + ArkAFIntent.consumePendingQuestion()（读即清空）→ 自动提交一次
   handleSend     → retrieval.retrieve(q,5,{cancel})（真实 RDB 片段）→ chat.ask(turn,onEvent)
   onPageHide/aboutToDisappear → currentCancel.cancel()（→ CloudModelProxy destroy）+ lease.release()
   引用点击       → router.pushUrl({ url:'pages/SourceDetail', params:{documentId,documentRevision,segmentId} })

AnatomyBrowser ─ 选中结构 → AnatomyStore.get(ctx).addHistory(id,name,systemId)   ← 历史写入点
```

## 6. 页面与路由参数

统一 `router.pushUrl({ url, params })`，**参数一律走 `params` 对象，禁止写进 URL 查询串**（本轮 #2 的根因）。`main_pages.json` 已注册 9 页。

| 路由 | 参数 | 说明 |
| --- | --- | --- |
| `pages/Index` | 无 | 首页（Lead 独占）；监听 `arkaf.pendingQuestion` 转跳问答 |
| `pages/AnatomyBrowser` | `AnatomyRouteParams { locateId?, locateName?, locateSystemId? }` | 带 `locateId` 时桥接就绪后定位选择；**选中即写历史** |
| `pages/StructureDetail` | `AnatomyRouteParams` | 结构名、所属系统、笔记编辑 |
| `pages/Favorites` | 无 | 条目 → `AnatomyBrowser`/`StructureDetail`（`buildLocateParams`） |
| `pages/History` | 无 | 同上 |
| `pages/KnowledgeQA` | 无（意图问题走 §9 通道） | 流式问答 + 引用点击 |
| `pages/KnowledgeManage` | 无 | 资料 CRUD；查看原文 → `SourceDetail` |
| `pages/SourceDetail` | `SourceParams { documentId, documentRevision, segmentId? }` | 展示片段原文/上下文；版本以库中当前值为准 |
| `pages/About` | 无 | 署名 |

**引用路由统一规范（本轮修复 #2/#7）**：
- 生产方（`KnowledgeQA` 引用点击）：`pushUrl({ url:'pages/SourceDetail', params: { documentId, documentRevision, segmentId } })`，三者取自 `SourceCitation`（`documentRevision` 必填）。
- 消费方（`SourceDetail`）：`router.getParams() as SourceParams`，缺 `documentId` → 空状态提示，不崩溃；有 `segmentId` → `resolveCitation(documentId, documentRevision, segmentId)` 判定过期后高亮。
- `KnowledgeManage`「查看原文」→ `params: { documentId, documentRevision: doc.revision }`（无 segmentId）。

参数缺失/非法时页面走「空状态 + 提示」，不得崩溃。

## 7. 真实知识库与问答服务：初始化 / 共享 / 释放（本轮修复 #1）

新增 **Lead 独占**文件 `ets/app/KnowledgeRuntime.ets`，作为进程内唯一的服务装配与生命周期所有者：

```ts
export interface IndexStatus { ready: boolean; indexedCount: number; pendingCount: number; }
export interface KnowledgeRuntimeOptions {
  useCloud?: boolean;          // 默认取 CloudConfig.CLOUD_FUNCTION_URL 是否非空
  cloudFunctionUrl?: string;
  model?: string;
}
export interface PageLease { release(): void; }

export class KnowledgeRuntime {
  static init(context: common.Context, opts?: KnowledgeRuntimeOptions): Promise<KnowledgeRuntime>;  // 幂等；并发调用共享同一 promise
  static shared(): KnowledgeRuntime;                                // 未 init 则抛 ServiceException(INDEX_NOT_READY)
  readonly container: ServiceContainer;
  readonly knowledge: KnowledgeService;
  readonly bridge: KnowledgeIndexBridge;
  indexStatus(): IndexStatus;
  onIndexStatus(cb: (s: IndexStatus) => void): () => void;          // 返回退订函数
  acquirePage(): PageLease;                                         // 引用计数 +1；页面持有期间订阅索引状态
  shutdown(): Promise<void>;                                        // bridge.stop()（仅 EntryAbility.onDestroy 或显式调用）
}
```

**初始化**：
1. `KnowledgeService.getInstance(ctx).ensureReady()`（建 `anatomy_knowledge.db`）。
2. `container = new ServiceContainer({ useCloud, cloudFunctionUrl, model })`。
3. `bridge = await container.connectKnowledgeService(knowledge)`：**全量同步当前文档的当前 revision 片段** + 订阅增量变更（这是「真实知识库」入口，取代内存 `seedDemoDocuments`）。
4. 初始化时机：`EntryAbility.onCreate` 在 `KnowledgeSeeder.seedIfNeeded()` 之后调用 `KnowledgeRuntime.init(this.context)`；页面亦可惰性调用（幂等）。任一路径都不得重复建实例。

**共享**：`KnowledgeRuntime.shared()` 为进程内单例。`KnowledgeQA`、`KnowledgeManage` 均通过它取服务，因此**索引与向量库全进程只有一份**，跨页保持一致，避免每页各建一份内存索引。

**释放**：
- **页面级**：页面 `aboutToDisappear` 调用 `lease.release()`：退订该页的 `onIndexStatus`、取消在途 `ChatHandle`；**不**停 bridge（保持索引热度）。
- **进程级**：`EntryAbility.onDestroy` → `KnowledgeRuntime.shutdown()`：`bridge.stop()` 退订变更、清理内存向量库。RDB 连接由 ArkData 管理，无需显式关闭。
- **禁止**页面自行 `new ServiceContainer` 或 `seedDemoDocuments`（E 删除 `KnowledgeQA` 中这两处引用）。

## 8. 资料版本同步策略

1. **版本号**：`CourseDocument.revision` 从 1 起，正文每次保存 +1（`KnowledgeService.updateDocument`）。
2. **片段版本**：`KnowledgeSegment.documentRevision` 记录生成时版本；重建时**先删该 `documentId` 全部旧片段再写新片段**（`replaceSegments`，本轮要求放进事务）。
3. **检索过滤**：仅使用 `segment.documentRevision === document.revision` 的片段（`getAllActiveSegments` 用 INNER JOIN 保证）。
4. **重建防覆盖**：`IndexSyncManager` 每份资料维护 `generation/currentRevision`；start 前与 embed 完成前各校验一次，generation 变化则丢弃本次结果。
5. **删除级联**：`deleteDocument` 删资料 + 级联删片段（**同事务**），并发 `deleted` 事件让 `IndexSyncManager.handleDocumentDeleted` 清向量。
6. **中断恢复**：`KnowledgeIndexBridge.start()` 先全量同步，再订阅增量；进程重启据此重建索引。
7. **向量一致性**：`VectorRecord{segmentId,documentId,documentRevision,vector}`；`MemoryVectorStore.upsert` 拒绝低 revision 覆盖高 revision。
8. **引用时效**：`SourceCitation.documentRevision` = 生成引用时版本；`resolveCitation` 返回 `CitationResolveResult`，`SourceDetail` 据此提示「资料已更新」。

## 12. ArkTS 严格模式编码约定

本项目 `.ets`/`.ts` 受 ArkTS 严格校验，以下写法**禁止**（否则编译失败）：

- `arkts-no-any-unknown`：不用 `any`/`unknown`；`catch (e)` 后按 `e instanceof Error` 取信息。
- `arkts-no-obj-literals-as-types`：不得用内联对象字面量当类型，必须声明具名 `interface`（含多字段返回值）。
- `arkts-no-untyped-obj-literals`：对象字面量必须可赋值给已声明类型（注解变量或 `as`）。
- `arkts-no-destruct-decls`：禁止解构（含 `for (const [k,v] of map)`）。
- `arkts-limited-throw`：只能 `throw` Error 子类。
- `arkts-no-in`：禁止 `in`；用可选方法存在性判断（接口声明 `method?()`）。
- `arkts-no-spread`：禁止对象展开 `{...a}` 与非数组展开。
- `arkts-no-implicit-return-types`：函数/箭头必须显式标注返回类型。
- `arkts-no-ctor-prop-decls`：禁止构造器参数属性；先声明字段再在构造体内赋值。
- `arkts-no-structural-typing`：类必须以 `implements` 显式实现接口。
- `Required<T>` 等映射类型不可用，改为显式接口。
- 全局 `fetch`/`TextDecoder` 不存在 → `@kit.NetworkKit` 的 `http`、`@kit.ArkTS` 的 `util.TextDecoder`。
- **文件类型边界**：`.ts` 不得 import `.ets`（`10605999`）；引用 ArkTS 模块的代码应写成 `.ets`。
- **import 相对路径**按目录层级写对（历史多处把子目录当 flat `service/`）。
- **`@Entry` 组件 `build()` 只能有一个根容器节点**；`Spacer` 非法，用 `Blank`。
- **UIAbility 生命周期签名必须精确**：`onCreate(want: Want, launchParam: AbilityConstant.LaunchParam): void`（同步、带参）。写成 `async onCreate(): Promise<void>` 不会被回调（本轮 #1 的隐藏根因）。

错误码速查：10505001 类型不匹配；10605008 any/unknown；10605040 对象字面量当类型；10605074 解构；10605087 throw 非 Error；10605066 `in`；10605099 spread；10605030 结构性类型；10605090 隐式返回类型；10605025 构造器参数属性；10605999 ts import ets；10905210 @Entry 多根节点。
