# 第一阶段 图像识别 Agent Prompts

目标：完成拍照/相册选图 → 端侧 YOLOv13 推理 → 检测框和分类计数 → 单次结果编辑的离线流程，同时完成 TaskPool 与耗时对比。RDB、JWT、云端同步和模型热更新安排到后续阶段。

执行顺序：Agent 0 完成契约和兼容性确认后，Agent 1、2、3 并行；Agent 4 数据与端云协同、Agent 5 测试与质量后置；最后由 Agent 0 进行最终集成与验收。以下内容为任务提示词。

## 公共工作规则

公共提示词已集中维护在项目根目录的 [AGENTS.md](../AGENTS.md)，其中包含模块地图、代码入口、文档索引、协作边界和验证方式。

每个 agent 从项目根目录开始工作，先读取 AGENTS.md，再使用下方对应角色的提示词。手工创建聊天时，可将以下引导语放在角色提示词之前：

```text
项目根目录：/Users/avery/Desktop/hongmeng/SmartItemRecognitionAssistant
先阅读项目根目录 AGENTS.md，按其文档地图定位当前任务涉及的代码与文档，再执行以下任务。
```

## Agent 0 接口与兼容性准备 先执行

```text
职责：为图像识别阶段建立最小共享契约，验证模型和推理库的接入前提。
你独占：docs/phase-1-contract.md、docs/phase-1-model.md、app/entry/src/main/ets/models/ 中的共享类型，以及确有必要的构建配置和依赖声明。任务完成后将推理依赖和模型相关文件的维护权交给 Agent 2。

1. 检查本地 DevEco SDK、模拟器架构及 onnxruntime-ohos 的维护方版本、原生库 ABI、API 和 TaskPool 使用约束。记录证据及所需配置。遇到兼容性问题给出可执行方案与阻塞点。
2. 确认 YOLOv13 官方模型来源。可用的 yolov13n.onnx 应记录来源、许可证、SHA-256、输入输出名称/形状/dtype、类别表、导出方式和 opset。官方仅提供权重时记录可复现导出步骤。根据实际模型确认输出是否带 objectness、是否已含 NMS；禁止凭其他 YOLO 版本猜测布局。
3. 固定最小接口：ImageSource、DetectionBox、DetectionResult、InferenceTiming、InferenceOptions 和识别状态。明确 RGB/像素格式、方向归一化、宽高、坐标单位、资源所有权和释放时机。
4. DetectionBox 使用方向归一化后原图的像素坐标。契约明确前置镜像与显示坐标转换由哪一层处理。明确跨 TaskPool 传递的数据以及 session 所在线程/生命周期，避免传递不支持序列化的对象。
5. 约定采集、推理、UI 的导出类/方法、参数、错误类型与调用示例，并列明 Agent 1/2/3 的最终文件归属。保持 API 足以完成任务。
6. 为样例图、阈值、NMS 策略、模型缺失和不支持 ABI 的处理确定一致行为。模型缺失时允许工程构建，但界面必须显示识别不可用。
7. 配置变更后验证构建；在文档中明确哪些兼容性已经实测，哪些待设备验证。
交付：共享类型、接口契约、模型与兼容性记录。完成后 Agent 1/2/3 才开始依照契约实现。
```

## Agent 1 图像采集

```text
职责：实现拍照与相册选图，并向其他模块提供契约规定的图像来源。
你独占：ets/services/camera/、ets/components/camera/，以及 module.json5 中相机权限和相关权限文案资源。路径均在 app/entry/src/main/ 下。首页由 Agent 3 维护。

1. 按契约提供相册选图服务，处理取消、文件读取失败、超大图和方向信息，明确 URI/文件访问有效期。
2. 使用 Camera Kit 实现应用内实时预览与拍照，按设备能力枚举支持的前后摄像头，提供切换。设备只暴露一个摄像头时显示合理状态。
3. 完成权限声明与运行时授权，处理拒绝、再次进入、后台恢复、退出页面及相机资源释放。
4. 与 Agent 3 约定预览组件的事件和图像返回值，传出方向及镜像所需信息，避免重复旋转或翻转。
5. 提供可复现的相册测试流程；相机不可用时保留相册识别入口。说明模拟器与真机各自的已测范围。
验收：授权后预览和拍照有效；选图取消不破坏已有结果；拒绝权限可恢复；重复进入退出相机不崩溃；支持的设备上切换相机成功。
```

## Agent 2 端侧模型与推理流水线

```text
职责：实现真实 YOLOv13 端侧识别和异步执行。
你独占：ets/services/inference/、ets/tasks/、resources/rawfile/models/，以及推理相关测试目录。接收 Agent 0 移交的 ONNX 依赖维护权。

1. 依据确认的模型元信息加载 onnxruntime-ohos session，验证模型输入输出格式和类别映射。
2. 实现 letterbox：保存实际缩放比例、舍入后的尺寸、上下左右 padding；完成正确颜色通道、归一化和 NCHW 转换。
3. 实现输出解析、置信度过滤、按类别 NMS、原图坐标还原与边界裁剪。NMS/置信度计算必须符合实际模型输出契约。
4. 同步与 TaskPool 模式复用同一算法。按库限制在后台任务所属上下文管理 session，避免将 UI 对象或不支持传输的原生句柄跨线程传递。
5. 串行执行推理；明确连续请求的丢弃或排队策略。对过期结果提供请求标识供 UI 拒绝回写；失败后恢复可用状态。
6. 分别统计预处理、模型推理、后处理耗时，单独记录首次加载/冷启动与总耗时。
7. 测试长宽图的坐标还原、padding 舍入、RGB/NCHW、同类重叠框抑制、异类保留、空结果、错误形状及阈值边界。尽可能使用同一图片与模型在可信参考运行时对照数值结果。
8. 测试替身与真实推理分离；报告实际运行的设备/ABI及模型 hash。运行阻塞时给出原始错误与复现步骤。
验收：真实图片能获得模型结果；检测框回到正确原图位置；高频触发时最多一个推理任务运行；错误后可以重试。
```

## Agent 3 识别页面与结果编辑

```text
职责：完成第一阶段用户界面，依据契约接入采集和推理服务。
你独占：ets/pages/Index.ets、ets/components/recognition/ 和该页面专用状态文件。保持公共类型由 Agent 0 管理、采集组件由 Agent 1 管理。

1. 提供拍照、相册选择、图片预览、开始识别、置信度阈值与同步/TaskPool 模式切换。
2. 显示初始化、识别中、成功、空结果、错误等状态。识别中约束重复触发；切换图片或离开页面后，旧请求结果不得覆盖新页面状态。
3. 将原图检测框映射到图片实际显示区域，正确处理 contain 留白、缩放、旋转和镜像。绘制类别与置信度，避免检测框随容器拉伸错位。
4. 展示分类计数；支持修正单个检测项类别、删除误检项，保证框、列表和计数一致。明确保留原始模型结果与当前编辑结果。
5. 显示三阶段耗时、总耗时和执行模式。增加可观察的交互探针或帧延迟记录，用于比较同步/异步期间的 UI 响应；避免把总推理时间标为界面响应时间。
6. 阈值变化采用契约约定策略，并明确展示结果对应的阈值。按钮和错误提示应帮助用户完成识别。
7. 允许独立开发时注入清楚标记的测试数据；交付时默认入口接入真实服务。
验收：横图、竖图、方图的框均对齐；编辑后计数更新；空结果和错误提示清晰；识别时异步模式仍能响应界面交互。
```

## 人工 Review 操作清单

先在 DevEco Studio 中打开项目 app/，同步依赖后运行构建。确认 Agent 0 模型说明中有文件来源、hash、输入输出与类别表。

| 场景 | 操作 | 通过标准 |
| --- | --- | --- |
| 真实推理 | 选择含水杯、手机、书本的清晰图片，查看日志和结果 | 能确认加载指定模型并产生实际检测输出；准确性逐图记录 |
| 框坐标 | 分别选择横图、竖图、方图及带方向信息的照片 | 图片方向正确，框对准物品，留白区域无系统性偏移 |
| 数量和编辑 | 使用多个同类物品图片，修改一项类别并删除一项 | 框、类别清单和计数同步更新 |
| 阈值 | 对同一图改变阈值并观察结果 | 展示结果与当前阈值一致，过滤规则可解释 |
| 空结果 | 选择空白或无目标图片 | 正常显示空结果，支持继续选图 |
| 权限 | 拒绝相机权限，再授权重试 | 提示明确，恢复后能使用相机 |
| 相机生命周期 | 多次进入退出预览，切后台恢复 | 相机资源释放正常，恢复后可继续拍照 |
| 前后切换 | 在暴露对应设备的环境中切换并拍照 | 预览、方向、拍摄结果正确；未暴露设备时合理禁用 |
| 高频输入 | 连点识别十次，随后切换图片 | 推理并发数最多为 1，旧结果不覆盖新图片 |
| UI 响应 | 同一图分别使用同步和异步模式，操作交互探针 | 异步模式保持响应，独立记录 UI 响应指标 |
| 模型异常 | 在测试构建中移除或替换损坏模型 | 显示明确错误，恢复模型后可重试 |
| 离线 | 模型已随包部署后关闭网络，再进行识别 | 图像识别流程仍可完成 |

准备至少 5 张自有测试图：单物品、多物品、重叠物品、横竖长图、空白图。记录图片来源和预期物品；模型误检漏检与工程坐标/统计错误分别登记。

人工验收记录建议：设备及系统版本、模型 hash、图片名称、操作步骤、预期/实际结果、截图、日志、结论。编译通过仅覆盖构建检查；真机性能数据另行记录。
